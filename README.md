## 一、先认识下 GoMami JPN Pulse：东京节点是个什么定位

GoMami Networks, LLC 是 Sharon（圈内人称"傻龙"）自家的 VPS 品牌，主打亚太优化线路，下游还挂着 ISIF、Neburst 等品牌，手里握着不少亚太优化带宽资源。它不靠"低价冲量"吃饭，而是把"中国大陆访问优化"这件事做到极致。

JPN Pulse 是它家日本东京的产品线，定位在三条产品线里属于"性价比工作马"那一档——比香港的 Turin 旗舰便宜，比同档香港 Pulse 多一个 Nano 入门款。机器跑在 **AMD EPYC 7773X**（Milan-X，带 3D V-Cache）或 **AMD EPYC 7K83**（Milan）上，基础频率 3.5GHz，全线标配 **CN2 GIA + AS9929 + CMIN2** 三网精品回程。

简单说：这是一台"用上代旗舰服务器 CPU + 三网顶级回程 + 大流量"的日本建站机，价格比香港同档低一档，比新加坡又多了更稳的联通回程。

## 二、硬件与网络：先看参数，再说人话

**硬件层**

- CPU：AMD EPYC 7773X / 7K83，3.5GHz 基频，最高 64 核

- 内存：DDR4，支持 ECC

- 存储：NVMe SSD（Gen4）

- 虚拟化：KVM

- 网络：VirtIO 端口，1–3 Gbps

- 备份：每日自动备份至 AWS S3（VPS 套餐默认包含）

EPYC 7773X 是 Milan-X 系列，最大卖点是把 L3 Cache 堆到了 768MB，对数据库、缓存类工作负载很友好。虽然主频不如香港 Turin 上的 EPYC 9575F（5GHz）那么夸张，但多核和缓存优势让它特别适合跑容器、多租户、MySQL InnoDB 这类"吃多核和缓存"的场景。

**网络层**

JPN Pulse 全系走"China Mainland Optimized Pro"路由，回程三网各自顶级优化：

| 运营商 | 回程线路 | 大致延迟（到广州） |

| --- | --- | --- |

| 中国电信 | CN2 GIA（AS4809） | 约 7–13ms 入口，30–40ms 落地 |

| 中国联通 | AS9929（CUII）精品 | 约 5–13ms 入口 |

| 中国移动 | CMIN2（AS58807） | 约 5–16ms 入口 |

去程走高 QoS 的 163 主干，回程走精品线路——这是目前亚太优化产品的第一梯队配置，和香港节点是同一套方案。

## 三、实测数据：晚高峰能不能扛住

光看参数没用，关键看晚高峰稳不稳。综合几份独立测评的数据，可以归纳出这么几条结论。

**回程路由（nexttrace 实测）**

国内三网回程基本是"香港 Next Hop → 三网各自精品入口 → 广州 → 落地"这条路径。电信走 CN2 GIA backbone，联通走 CUII（9929）backbone，移动走 CMIN2 直接进 CMNET。三网都不绕、不掉包，路由干净。

**带宽实测**

- 单线程下载：电信 178–307 Mbps，联通 350 Mbps 左右，移动 280 Mbps 左右（被 QoS 上行，下行正常）

- 多线程 / 国际互连：Speedtest.net 跑出 1988 Mbps 上行、1879 Mbps 下行，1ms 延迟

- 国际互联到新加坡：360/613 Mbps，35ms 延迟

需要注意的是，移动用户上行会被运营商侧 QoS（这是运营商行为，不是 GoMami 的锅），下行基本不受影响。如果你的业务以下行为主（看视频、下载、API 拉取），三网体验都很猛；如果做直播上行，移动用户要心理预期一下。

**晚高峰表现**

这是 GoMami 最被社区称道的一点：晚上 9–11 点的黄金时段，很多"中国优化"VPS 会偷偷掉速，而 GoMami 基本还能维持标称带宽。多位独立测评者都印证过这一点——"晚上能跑出白天速度的供应商，整个亚太没几家"。

**IP 质量与流媒体**

日本节点的 IP 质量属于"常规流媒体基本解锁"水平：Netflix、Disney+、Amazon Prime、YouTube、ChatGPT（仅 App）、Steam 商店等都能正常用；Gemini、Sora 这类严格风控的会被识别。当落地机用没问题，但当日本本土专属服务（如部分日本本地限定内容）解锁能力一般。

## 七、JPN Pulse 适合谁，不适合谁

**适合**

- **跨境建站用户**：业务面向中国大陆 + 日本本地，希望日本节点同时覆盖中日韩三地用户

- **个人开发者 / 站长**：跑个人博客、轻量 SaaS、API 服务、监控机器人，2G/4G 内存档就够

- **容器化 / 多租户场景**：EPYC 7773X 的大 L3 Cache 对 Docker、K8s node、多容器并发很友好

- **预算中等、追求线路质量的用户**：$29 起步比香港 $49 起步友好，又能拿到同一套三网精品回程

- **想跑日本本地业务但需要兼顾国内访问的**：东京 IP 对日本本土服务认可度高于香港，回程又能拉回中国大陆

**不太适合**

- **预算只有每月几块钱的个人用户**：$29 的 Nano 已经是 GoMami 全系最低门槛，再往下不在这个品牌的赛道里

- **对移动用户上行有强需求的（直播推流等）**：移动侧 QoS 是运营商行为，GoMami 改不了，香港节点更严重

- **追求极致单核性能的**：3.5GHz 主频不如香港 Turin 的 EPYC 9575F（5GHz），跑数据库高频交易这种"吃单核"的场景，香港 Turin 更对路

- **需要解锁日本本土限定流媒体的**：JPN Pulse 的 IP 解锁能力属于"通用流媒体 OK，日本本土专属一般"水平

- 用户主要走移动、需要覆盖东南亚 → 新加坡 Pulse

如果你的业务同时面向中国大陆 + 日本本土 + 韩国用户，JPN Pulse 的覆盖广度是三地最好的——这是 meowvps 等独立测评里反复提到的"东京覆盖优势"。

## 十、最终结论：JPN Pulse 是不是一台好机器

适合"预算够、要求线路质量、业务需要覆盖中日韩"的用户；不适合"追求极致低价"或"只追求极致单核性能"的用户。
